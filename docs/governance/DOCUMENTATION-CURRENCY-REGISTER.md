# Documentation Currency Register

Produced by CC-12E as a compact, efficient audit of repository documentation currency — not a rewrite of every document; corrected by CC-12E.1 after independent Project Architect review found CC-12E's own conclusion was **false-green**. Statuses:

- **AUTHORITATIVE_CURRENT** — accurate, owns the fact(s) it states, no correction needed.
- **CURRENT_WITH_MINOR_UPDATE** — accurate after a small correction made in this package.
- **STALE_REQUIRES_UPDATE** — found materially stale; not corrected in this package (none currently open — see below; four were found and corrected by CC-12E.1, listed under "CC-12E.1 correction" in the register).
- **SUPERSEDED_ARCHIVE/HISTORICAL** — correctly describes a past state; not current authority, not rewritten.
- **DUPLICATE_SOURCE_OF_TRUTH** — overlaps another document's owned fact; flagged, not merged (none required a merge this pass).
- **UNCLEAR_OWNERSHIP / NOT AUDITED THIS PASS** — large or low-churn document not read in full this pass; a targeted grep for known stale terms found nothing wrong in it.

## CC-12E.1: the false-green finding

CC-12E's Tier-1 audit method was **keyword grep against a predetermined list of ten known-stale terms** (old release versions, `/learn/[family]`, `RightHandGripRuleDiagram`, the disconnected artwork manifest, "no scrolling" hard rules, assessment conflation, mandatory per-lesson exams, deprecated tooling, the old static lesson screen, the pre-rename lock name). That method genuinely found zero hits in Tier-1 docs — correctly reported — but it **missed semantically stale prose that used none of those exact terms**: statements like "the lesson player is not implemented", "implementation has not begun", "a future native client is expected", "no visual has been through that workflow yet", and a "Last accepted implementation commit" section frozen at CC-08. None of these matched a searched term, so none were flagged, and CC-12E's register classified the documents containing them as current or only-minorly-updated. Independent Project Architect review caught this. **The lesson: keyword grep proves the absence of specific known-bad phrases; it does not prove the presence of true, current claims.** A document's own header/status framing, current-system-topology description, and "current/future/not yet/last accepted" language are exactly the highest-volatility prose in any living architecture document — they need to be read and semantically compared against `PROJECT-STATUS.md`/real implementation evidence every time, not only grepped.

## Method (revised by CC-12E.1)

Tier 1 (read in full or near-full): README, PROJECT-STATUS, START-HERE, ROADMAP, ARCHITECTURE-OVERVIEW, PROJECT-CONSTITUTION, PRODUCT-PRINCIPLES, DECISION-LOG, DOCUMENTATION-STANDARD, LESSON-PLAYER-AND-LESSON-PLAN-ARCHITECTURE. Tier 2 (targeted grep across every file under `docs/` plus README/PROJECT-STATUS/CONTRIBUTING for known-stale terms). Tier 3 (historical evidence/research documents): filenames inventoried, not read line-by-line.

**New standing rule, added by CC-12E.1, for every future currency pass over a Tier-1 document:** beyond keyword grep, semantically review that document's own header/status statement, its current-system/topology description (if any), and every sentence containing "current", "future", "not implemented", "not yet", "implementation has not begun", "next", "last accepted", or "not yet built" — compare each one against `PROJECT-STATUS.md`'s live package history, not only against the searched-term list. This is a review discipline, not new tooling — no documentation-linting engine is being built for this.

## Findings from the keyword-grep pass (still valid)

The original ten-term keyword search (old release versions as current, `/learn/[family]`, `RightHandGripRuleDiagram` as current source of truth, the disconnected artwork manifest / stale canonical-visual-registry, "no scrolling"/"one viewport" hard rules, question/assessment conflation, mandatory per-lesson exams, deprecated tooling, the old static lesson screen, the pre-rename `CANONICAL_TEACHING_VISUAL_LOCK` name) genuinely found zero hits in Tier-1/2 documents outside dated changelog entries or labelled evidence snapshots — that specific finding still stands. What it did **not** find, and what CC-12E.1 corrected, is documented above: four Tier-1 stale claims that used none of those ten terms (ARCH-003's header/§5/§7/§10/§15/§16; ARCHITECTURE-OVERVIEW's system-shape diagram; PROJECT-STATUS's visual-workflow trigger; PROJECT-STATUS's frozen "Last accepted implementation commit" section).

## Corrected overall conclusion

**CC-12E's original conclusion — "the documentation was already substantively clean, only missing current-state entries" — was false-green and is withdrawn.** The corrected conclusion: this repository's documentation discipline (single-owner rule, dated changelog entries, explicit historical-snapshot labelling) is genuinely strong at the *changelog/evidence* layer, which is why the keyword search found nothing wrong there — but the *durable architecture documents* (ARCH-001, ARCH-003) had drifted materially behind real implementation in their own header/status framing, and that class of staleness requires the semantic review discipline recorded above, not keyword search alone. Both are now corrected; the standing rule exists so a future currency pass catches this class of drift without needing another independent-review escalation to find it.
