# Documentation Currency Register

Produced by CC-12E as a compact, efficient audit of repository documentation currency — not a rewrite of every document; corrected by CC-12E.1 after independent Project Architect review found CC-12E's own conclusion was **false-green**. Statuses:

- **AUTHORITATIVE_CURRENT** — accurate, owns the fact(s) it states, no correction needed.
- **CURRENT_WITH_MINOR_UPDATE** — accurate after a small correction made in this package.
- **STALE_REQUIRES_UPDATE** — found materially stale; not corrected in this package (none currently open — see below; four were found and corrected by CC-12E.1, and five further semantically-stale points were found and corrected by CC-13A, each listed under a "CC-12E.1 correction" or "CC-13A correction" note in the register).
- **SUPERSEDED_ARCHIVE/HISTORICAL** — correctly describes a past state; not current authority, not rewritten.
- **DUPLICATE_SOURCE_OF_TRUTH** — overlaps another document's owned fact; flagged, not merged (none required a merge this pass).
- **UNCLEAR_OWNERSHIP / NOT AUDITED THIS PASS** — large or low-churn document not read in full this pass; a targeted grep for known stale terms found nothing wrong in it.

## CC-12E.1: the false-green finding

CC-12E's Tier-1 audit method was **keyword grep against a predetermined list of ten known-stale terms** (old release versions, `/learn/[family]`, `RightHandGripRuleDiagram`, the disconnected artwork manifest, "no scrolling" hard rules, assessment conflation, mandatory per-lesson exams, deprecated tooling, the old static lesson screen, the pre-rename lock name). That method genuinely found zero hits in Tier-1 docs — correctly reported — but it **missed semantically stale prose that used none of those exact terms**: statements like "the lesson player is not implemented", "implementation has not begun", "a future native client is expected", "no visual has been through that workflow yet", and a "Last accepted implementation commit" section frozen at CC-08. None of these matched a searched term, so none were flagged, and CC-12E's register classified the documents containing them as current or only-minorly-updated. Independent Project Architect review caught this. **The lesson: keyword grep proves the absence of specific known-bad phrases; it does not prove the presence of true, current claims.** A document's own header/status framing, current-system-topology description, and "current/future/not yet/last accepted" language are exactly the highest-volatility prose in any living architecture document — they need to be read and semantically compared against `PROJECT-STATUS.md`/real implementation evidence every time, not only grepped.
