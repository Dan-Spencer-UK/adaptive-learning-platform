# Decision Log

| Date | Decision | Rationale / notes |
|---|---|---|
| 2026-08-14 | Initial launch has no learner-runtime AI dependency. | AI is used for development/content production; a future AI tutor may be a separate premium feature. |
| 2026-08-14 | Use selective shadcn/ui open-code primitives for commodity UI mechanics. | Avoid rebuilding solved accessible controls while preserving project-owned learner UX/design. |
| 2026-08-14 | Replit is not part of the canonical development workflow. | Local Git + VS Code + bounded Claude Code + review provides stronger architectural control. |
| 2026-08-14 | `PROJECT-STATUS.md` is the sole authoritative home for live current state. | Prevent drift caused by multiple handover/current-state documents. |
| 2026-08-15 | Native iOS and Android are the primary learner platforms; web is secondary. | Prior documentation implicitly framed the web/Next.js client as the primary learner surface; this corrects that for all future work. Opened as CC-04M (governance/evaluation stage). The specific native technology (React Native/Expo or otherwise) is deliberately not decided here and requires its own future ADR before implementation. |
| 2026-08-15 | CC-04M formally accepts Expo + React Native (React Native New Architecture) as the native-client technology. | See [`ADR-0001`](../architecture/adr/ADR-0001-mobile-client-technology.md) (status: accepted) for the full decision, alternatives considered and rationale. Closes the deferred-technology-choice item recorded above. |
| 2026-08-21 | The first complete qualification-scale target is full City & Guilds 2365-02 Unit 202 (Principles of Electrical Science); the Coverage & Assessment Matrix is a derived report, never a second authored source of truth. | CC-09A. Official specification defines WHAT must be learned; official public sample/mock material may inform HOW assessment is structured (pattern metadata only); learner-facing questions remain independently authored original content; foundational knowledge stays generic/reusable beneath vocational capabilities. Whole-Unit-202 implementation proceeds in bounded Sonnet batches, see `PROJECT-STATUS.md` §CC-09A. |
| 2026-08-21 | `AssessmentSpecification` (official test structure: duration, question count, permitted materials, per-Learning-Outcome allocation) is a new small governed contract; `AssessmentBlueprint` (a future deterministic mock-paper assembler) is deferred -- YES LATER, not built now. | CC-09A. Reuse-over-new-architecture was preferred everywhere else (curriculum coverage is computed from existing manifests, never a new authored entity); this is the one genuinely new fact `AssessmentSpecification` represents that no existing contract could. `AssessmentBlueprint` has nothing to consume yet beyond what this contract plus the existing `QuestionBlueprint`/`GeneratedQuestionInstance` contracts already provide. |
| 2026-08-21 | `RANGE_ITEM` is added to the governed curriculum-node-type vocabulary, parented under `ASSESSMENT_CRITERION`. | CC-09A. Official City & Guilds "Range" boxes name individually mandatory items (58 across Unit 202) that a truthful complete-coverage claim must enumerate and trace mechanically -- previously representable only as prose in a code comment. |
| 2026-08-21 | An AI model's own extraction of externally anchored governed content (curriculum structure, assessment specifications, source-derived corpus mappings, sample-assessment observations) is never sufficient by itself to count as verified -- independent verification by the Project Architect/ChatGPT role (never the Product Owner as a routine step, never the same model that authored the extraction) is required before such content is treated as `VERIFIED`. | See [`ADR-0002`](../architecture/adr/ADR-0002-external-source-verification-and-currency.md) for the full decision. Directly motivated by a caught pre-CC-09A curriculum-extraction error (a stale seven-LO structure mistaken for current). |
| 2026-08-21 | Externally anchored source versions carry snapshot identity (retrieved date, SHA-256 content fingerprint, verification status/verifier, last currency-check date); a source change never silently mutates an existing internal governed version -- it creates an update candidate requiring detection, independent verification, impact analysis and a new governed version/release. | See [`ADR-0002`](../architecture/adr/ADR-0002-external-source-verification-and-currency.md). Extends the existing `sourceVersion` entity; no new entity created. A future periodic currency-check maintenance job is a tracked backlog item, not built by this decision. |
