# Unit 202 whole-course instructional-visual needs matrix (CC-11.3)

Generated by hand during CC-11.3's discovery phase (8 parallel LO/topic
discovery agents + main-agent reconciliation), recorded here as the
discrete artefact task brief §4/§28 asks for. Classification is derived
from lesson/capability/misconception/objective -> need, never from
"an existing visual -> where can we use it". `check-visual-completeness.ts`
mechanically re-derives the REQUIRED column's satisfaction (asset,
renderer, contract, lesson-reference, symbol-convention) on every run --
this file records the classification decision itself, which is a
pedagogical judgement, not a mechanically-derivable fact.

Status column: **REQUIRED (satisfied)** = the lesson has a governed,
rendered, contracted visual wired into a step. **NOT_NEEDED** = the
content is purely numeric/algebraic/definitional; a diagram would be
decorative, not instructional. **USEFUL (deferred)** = a visual would
plausibly help but is not essential to the specific assessed objective,
and building it was judged lower priority than closing every REQUIRED
gap first (task brief §34: "prioritize highest-pedagogical-value USEFUL
visuals if time remains after REQUIRED is complete" -- honestly recorded
here as deferred, not silently dropped).
