## 3. EDA-LP-16 (component schematic symbols) -- RESOLVED

**Product Architect decision (Section 4 of this pass's brief):** qualification-depth symbol recognition does not require proof of every symbol's current IEC database status. The course must not claim an older or course-defined representation is the current IEC 60617 form unless directly verified; every learner-facing shape must have a genuine, read source or be transparently a course diagrammatic convention; an inverter may be a clearly labelled functional DC-to-AC block if no unique universal schematic symbol exists, never invented or called a standard symbol; the LED needed a directly-read, permitted-class source for its symbol geometry before being taught as an externally established symbol.

**Bounded acquisition pass:** the SAME already-registered IEEE Std 315-1975/ANSI Y32.2-1975 standard (`SRC-IEEE315-1975-ANSI-Y32-2-GRAPHIC-SYMBOLS`) was personally re-opened as page images this pass -- not read from memory or a prior search snippet. **LED:** item 8.5.4.2 "Photoemissive type" (page 56), grouped under 8.5.4 Photodiode alongside 8.5.4.1 "Photosensitive type" (light-sensing, arrows toward the device), draws a diode-in-envelope symbol with two arrows directed AWAY from the device -- i.e. a photodiode that emits rather than senses light -- cross-referenced "See also item 11.1.1". Item 11.1.1 "Lamp, general; light source, general" (page 63) draws the identical two-outgoing-arrows convention, and its own NOTE 11.1.1B letter-code list explicitly includes "LED -- Light-emitting diode" as an annotation applicable to that exact symbol family. **Inverter:** item 16.1.1 "General" (page 74) draws a plain rectangle with an asterisk placeholder; NOTE 16.1C, read directly on the same page, states this general circuit-element symbol's use "is restricted to: ... (c) Applications where a specific graphic symbol ... do[es] not appear elsewhere in this standard" -- the standard's own stated policy positively confirms no dedicated inverter symbol exists, rather than this pass merely failing to find one. Item 16.1.1.2 lists "ST-INV -- Static inverter" as the applicable letter code for that block.

**Result:** breadth is closed for all 15 named AC6.2 families -- 14 with a genuinely evidenced dedicated symbol, 1 (inverter) with a directly-evidenced, standard-sanctioned absence of one. The requirement's `verificationStatus` moves `PARTIALLY_VERIFIED` -> **VERIFIED**; `EDA-LP-16`'s `evidenceReadiness` moves `HELD_PENDING_EVIDENCE_CORRECTION` -> **READY**. Per the Product Architect's decision, the inverter is taught/assessed only as a clearly labelled DC-to-AC functional block, never as a claimed standard component symbol; the LED is taught as the diode symbol with two outgoing light arrows. The words "standard"/"current IEC"/"IEC 60617" are used in the learning point's own content only to the extent directly established -- the requirement's evidentiary basis throughout remains the 1975 standard, not a claim of current-IEC-60617-database confirmation, and that currency caveat remains explicitly disclosed (now additionally at the facet level, see Section 2 above) rather than silently dropped. The six-identity IEC 60617 webstore preview confirmation (validator check 27) remains explicitly disclaimed in its own record as **not** the basis for this requirement's status -- the upgrade rests entirely on the independent 1975-standard breadth closure.

**EDA-LP-16 was the sole remaining core (non-context) release blocker across the whole 133-point curriculum. Zero remain after this correction.**
